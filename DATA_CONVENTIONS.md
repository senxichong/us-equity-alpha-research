# Data conventions

## Scope and timestamps

Phase 1 only. Daily USD US equity observations; no signals, model fitting or portfolio computation. The primary sample is a deliberate stress sample, not an index reconstruction. `date` is the America/New_York trading-session date, stored as a timezone-naive date label. Vendor timestamps remain timezone-aware in raw Parquet; original Yahoo JSON keeps Unix timestamps and exchange metadata. Never derive a session date by stripping the UTC timezone before converting to the exchange timezone.

The configured interval is start-inclusive, end-exclusive. The run uses XNYS sessions whose official close precedes the run timestamp and the configured endpoint. The configuration is frozen to the client date 2026-10-08, so the last requested complete US session is 2026-10-07. Early closes and exchange holidays come from the locked exchange-calendars package. XNYS is a common US-equity session proxy; security-specific halts require separate investigation. Coverage does not assume every missing date is an error.

## Raw does not mean as-traded

`data/raw` means the unmodified response snapshot, not an assurance that price values are unadjusted. The Yahoo public chart adapter saves response bytes and a table containing vendor OHLC, Adj Close, Volume and event fields. Extracting the table maps event timestamps to exchange dates but does not repair prices. The yfinance adapter explicitly uses `auto_adjust=False`, `back_adjust=False`, `repair=False`, `keepna=True`, `actions=True`, and no rounding; it failed during this run and is not the recommended working transport.

Yahoo OHLC/Close already reflects splits and can reflect distribution/spin-off normalization. Yahoo Adj Close additionally incorporates vendor dividend/distribution adjustments. GE and O contain non-integer events under the vendor's `splits` field: these are not all ordinary splits and must not be turned automatically into share-count multipliers. Volume is retained exactly as delivered; no dividend factor is applied to it. An independent proof of historical volume share-basis is still missing. Do not combine this volume with unverified historical shares outstanding to manufacture market caps or turnover.

Yahoo documentation and implementation references: [historical prices](https://finance.yahoo.com/quote/AAPL/history/), [yfinance history API](https://ranaroussi.github.io/yfinance/reference/api/yfinance.Ticker.history.html). The installed `yfinance/utils.py::auto_adjust` uses `Adj Close / Close` to scale OHLC; this project implements the same explicit ratio while retaining both sets of columns.

## Price and return fields

| Purpose | Required convention |
|---|---|
| Data validation | Compare vendor open/high/low/close on the same basis; do not compare high/low with dividend-adjusted close. |
| Future return research | `adj_close[t] / adj_close[t-1] - 1`, within one frozen provider snapshot and over consecutive exchange sessions. This is a vendor-adjusted return proxy. |
| Future momentum | Ratios of `adj_close` over explicitly defined, lagged session windows. No computation in Phase 1. |
| Future volatility | Historical consecutive-session returns from `adj_close`, with a past-only window. No computation in Phase 1. |
| Adjusted OHLC | `adjusted_x = vendor_x * adj_close / close`; preserve the originals and adjustment factor. |
| Future portfolio PnL | Not implemented or certified. Ideal ledger uses true execution prices, split-adjusted holdings, explicit cash distributions, costs and terminal delisting proceeds. An adjusted-return proxy must not add dividends a second time and must not be called executable PnL. |

Never calculate a ratio with close in one endpoint and adjusted close in the other. Never apply a split a second time to Yahoo Close. Never multiply historical Yahoo Close by today's share count to infer historical capitalization. Adjusted levels may be retrospectively rebased: even though common scale factors cancel in within-window ratios, this is not a historical-vintage database and does not establish all features were available at the time.

`session_returns` is a unit-tested alignment primitive only. It reindexes each security to the explicit exchange calendar without filling. Trailing return at t uses t-h to t; a forward label at t uses t to t+h and remains missing at the terminal h sessions. Missing endpoints remain missing; a gap is never relabeled as a one-session return. No research factors or dataset labels are generated by this phase. Knowing the close at t does not authorize execution at that same close; future research must state information and execution times separately.

## Corporate-action verification

For ordinary splits, the diagnostic checks the event date/ratio and surrounding vendor Close change. A split-adjusted series should not mechanically fall by 75% on a 4:1 split; ordinary market movement still exists. Official spot checks use [AAPL ex-distribution 2020-08-31](https://infomemo.theocc.com/infomemos?number=47370) and [NVDA split-adjusted trading 2024-06-10](https://www.sec.gov/Archives/edgar/data/1045810/000104581024000144/nvda-20240607.htm). These two checks do not certify every event.

For dividends define F[t] = AdjClose[t]/Close[t]. Check `F[t-1]/F[t]` against `1 - dividend[t]/Close[t-1]`, using a configurable absolute tolerance. This tests the vendor's backward adjustment consistency; it is not proof of the exact cash-reinvestment return `(Close[t]+D[t])/Close[t-1]-1`. Backward dividend adjustment and explicit cash accounting can differ. Concurrent distributions, spin-offs, taxes, rights and delisting compensation need separate treatment.

`split_adjust_as_traded` exists only as a tested transformation for genuinely as-traded synthetic inputs: divide a historical price by the product of subsequent new/old share ratios, excluding the event on the price date. It is never applied to the downloaded Yahoo sample.

## Cache and provenance

Request settings determine the cache key; successful and failed responses are cached. Every successful price snapshot records retrieval UTC, source/request, timezone, version or vendor metadata, and SHA-256. Yahoo chart saves original JSON before parsing. New downloads with `--refresh` create new timestamped files; prior snapshots are retained. Cache loads verify hashes and do not use the network. Raw and processed data never share files. Each run saves its own configuration, manifest, validation and action details; `reports/*.json` are convenience pointers to the latest run, not the archive.

Re-fetching later is not guaranteed to reproduce historical bytes. Reproducing a result means using the archived snapshot and dependency lock. Raw vendor data is excluded from Git; share code and diagnostics, and review source licensing before redistributing data. A public endpoint does not grant unrestricted redistribution rights.

## Phase 2 addendum (2026-10-08)

The user now authorizes a broad prototype dataset despite unresolved PIT membership. Existing price and time definitions above remain unchanged. The Phase 2 requested start is 2010-01-01; Phase 1's sample configuration and archived reports remain available. All Phase 2 result metadata declares `survivorship_biased=true` and `security_identity_verified=false`.

The dense panel starts at each admitted security's first available observation and contains one row per subsequent completed session. Missing sessions remain null and flagged. Zero-volume bars remain in raw storage; all their financial fields are null in the research panel and `is_valid_observation=false`. No forward/backward price, volume or event fill is performed. Dates before available history are not fabricated; a vendor firstTradeDate comparison identifies plausible short listings but does not certify an IPO or identity chain. Minimum history is evaluated per date, not retroactively assigned.

Admission thresholds are predeclared in config.yaml. Serious validation failures quarantine the whole ticker. Extremes and noninteger events may be economically genuine but remain quarantined without case-by-case verification. Current liquidity ranking uses recent median vendor Close × Volume as a proxy, not certified as-traded turnover. Current membership, recent liquidity and full-period quality exclusion all introduce disclosed selection bias.

Incremental updates preserve every source response, replace overlapping dates explicitly and test for revisions. New splits/dividends or material overlap differences trigger a full-history refresh instead of unsafe adjusted-price splicing. Slight differences within configured floating-point tolerance are recorded implicitly by snapshot lineage; revisions outside the overlap can go undetected until periodic or explicit full refresh. No daily history is asserted to be historically point-in-time.

Yahoo sometimes includes action events outside the requested time interval. Phase 2 records those events in attempt metadata and preserves them in the original JSON, while omitting them from the requested-window table. An unmatched event inside the requested interval remains a failure; no holiday event is silently shifted to a trading day.
